# Помощник ИИК

Telegram-бот на **aiogram 3** для поступающих и первокурсников Института информатики и кибернетики Самарского университета. Содержание перенесено из документа «Структура_бота_помощника_ИИК.docx».

## Возможности

- Выбор «Поступаю» / «Уже зачислен» с разным порядком восьми разделов.
- Поступление, общежитие, справки, ВУЦ и воинский учёт, учёба, стипендии, кампус, клубы и карьера.
- Короткие карточки с действиями, документами, контактами и ссылками на источники.
- Общие карточки медицинского допуска и отсрочки доступны из нескольких разделов.
- Постоянные кнопки «Главное меню», «Назад», «Контакты», поиск по тексту и ключевым словам.
- SQLite сохраняет роль и путь по меню после перезапуска. Тексты сообщений в базе не хранятся.
- `/privacy` объясняет хранение данных; `/forget` удаляет данные пользователя из базы бота.
- Просроченные сезонные сведения скрываются; остаются контакт и официальный источник.

Бот работает в личных чатах. Внешняя база данных и платные API для его работы не требуются.

## Установка и запуск

Нужны Python **3.11+**, [uv](https://docs.astral.sh/uv/getting-started/installation/) и токен бота от [@BotFather](https://t.me/BotFather).

```bash
cd /workspace/IIKBotHelper
UV_CACHE_DIR=/workspace/.cache/uv uv sync --locked --extra dev
cp -n .env.example .env
```

Укажите настоящий `BOT_TOKEN` в локальном `.env` или безопасных настройках среды. Не отправляйте токен в чат и не добавляйте `.env` в Git. Переменные процесса имеют приоритет над `.env`.

Проверка без токена и без обращений к Telegram:

```bash
.venv/bin/python -m iik_bot --check
.venv/bin/pytest -q
.venv/bin/ruff check .
```

Запуск:

```bash
.venv/bin/python -m iik_bot
```

После подключения откройте своего бота в Telegram и отправьте `/start`. Проверьте выбор роли, раздел «Общежитие», переход к медицинскому допуску и возврат кнопкой «Назад». Остановка — Ctrl+C.

Используется **long polling**; публичный сервер, порт и webhook не нужны. Если у этого токена уже настроен webhook, приложение остановится с объяснением: удалите webhook через Telegram API осознанно либо используйте отдельного бота для разработки. Одновременно запускайте только один polling-процесс с одним токеном.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен от BotFather |
| `DATABASE_PATH` | По умолчанию `data/bot.sqlite3`, относительно рабочего каталога |
| `CONTENT_PATH` | Необязательный путь к собственному JSON-каталогу |
| `LOG_LEVEL` | `INFO` по умолчанию; также `DEBUG`, `WARNING`, `ERROR`, `CRITICAL` |

Путь к базе должен быть доступен для записи. Каталог `data/` нужно сохранять между перезапусками и включать в резервные копии, если требуется сохранение профилей. Для резервной копии работающей SQLite используйте её backup API либо останавливайте процесс перед копированием базы и сопутствующих файлов. Ограничьте доступ к базе на сервере: она содержит Telegram ID.

Для работы бота нужен HTTPS-доступ к **`api.telegram.org`**. Клиент учитывает стандартные `HTTPS_PROXY` / `NO_PROXY` и системные доверенные сертификаты (`SSL_CERT_FILE` / `SSL_CERT_DIR`, если они настроены). Проверка TLS включена. Домены сайтов университета нужны пользователям для открытия ссылок; бот не загружает их страницы при каждом ответе.

Для облачной среды сохраняются скрипт установки, инструкции запуска, разрешение домена Telegram и требование секрета `BOT_TOKEN`. Черновик настроек нужно сохранить и опубликовать средствами платформы; сохранение черновика само по себе не запускает бота. Исходники в этой задаче ещё не отправлены в удалённый репозиторий.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие; выбор роли при первом запуске |
| `/menu` | Все разделы |
| `/role` | Сменить роль |
| `/contacts` | Контакты служб |
| `/search отсрочка` | Найти тему; обычный текст также запускает поиск |
| `/help` | Помощь |
| `/privacy` | Хранение данных |
| `/forget` | Удалить сохранённую роль и историю навигации |

## Редактирование содержания

Каталог: [`src/iik_bot/content/catalog.json`](src/iik_bot/content/catalog.json). Контакты и источники хранятся отдельно от карточек и переиспользуются по ID. Поля карточки:

| Поле | Содержание |
| --- | --- |
| `title`, `text` | Заголовок и короткий ответ, обычный текст без HTML |
| `steps`, `documents` | Шаги и перечень документов |
| `children` | Кнопки `{ "label": "…", "target": "id_карточки" }` |
| `contact_ids`, `source_ids` | Ссылки на общие контакты и HTTPS-источники |
| `keywords` | Дополнительные поисковые слова |
| `checked_at` | Дата реальной проверки редактором, `YYYY-MM-DD` или `null` |
| `campaign_year` | Год сезонной кампании или `null` |
| `expires_on` | Последний день действия, `YYYY-MM-DD` или `null` |

Перед публикацией датированной информации задайте год и/или срок действия. При несовпадении года или истечении срока бот скрывает текст, шаги и документы этой карточки, сохраняя ссылки и контакты. Сезонные данные размещайте в отдельной карточке, чтобы не скрывать вместе с ними постоянные сведения.

После редактирования выполните `python -m iik_bot --check` из активированной `.venv` и тесты. Каталог читается при запуске; для применения изменений перезапустите бота. Проверка находит несуществующие переходы, неизвестные контакты и источники, недоступные карточки и превышение лимитов Telegram. Проверка URL устанавливает корректность формата, но не актуальность страницы.

Дата `document_review_date` — дата источников, указанная в документе, а не подтверждение нашей независимой проверки всех сведений. Поэтому `checked_at` у перенесённых карточек оставлен `null`. Неподтверждённые дедлайны приёма, суммы стипендий и старые анонсы не выданы за действующие. Тарифы общежитий подписаны датой из документа. Оставшиеся редакторские задачи перечислены в [`docs/CONTENT_REVIEW.md`](docs/CONTENT_REVIEW.md).

## Разработка

```bash
UV_CACHE_DIR=/workspace/.cache/uv uv sync --locked --extra dev
.venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

`uv.lock` фиксирует зависимости. Исходники находятся в `src/iik_bot/`; обработчики — в `handlers.py`, навигация и представления — в `handlers.py` и `views.py`, SQLite — в `storage.py`. Тесты направляют настоящие aiogram `Update` в `Dispatcher` с подменой транспортной сессии: проверяется логика обработки без отправки сообщений людям.

Тесты без токена не подтверждают доступ к Telegram, действительность токена или актуальность данных университета. Финальная проверка с собственным ботом проводится после настройки токена и сети.

## Деплой с Python 3.11 (INFRLO Buildpack)

В корне репозитория находится `requirements.txt`, который устанавливает само приложение из `pyproject.toml`. Для сборки используйте `pip install -r requirements.txt`, для запуска — `python -u -m iik_bot`. Рабочий каталог должен содержать `pyproject.toml`. Python 3.11.17 проверяется теми же локальными тестами, что и Python 3.12.

Задайте `BOT_TOKEN` в переменных окружения хостинга. Нужен постоянно работающий процесс с HTTPS-доступом к `api.telegram.org`. В журнале после запуска должно появиться сообщение «Бот запущен в режиме long polling». Сохраните базу `data/bot.sqlite3` на постоянном диске, если платформа очищает файловую систему при пересоздании контейнера.
